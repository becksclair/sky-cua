# Plan: KWin and X11 Workspace Metadata

## Goal

Populate `WindowInfo.workspace` for KWin and X11 window registry entries when the underlying window manager exposes a numeric workspace/desktop value.

## Status

Implemented.

The original gap was that `crates/sky-cua-linux/src/windowing/registry.rs` converted KWin and X11 windows with `workspace: None` even though other backends could carry workspace data. That is now fixed.

## Current Implementation

### KWin

- `crates/sky-cua-linux/src/kwin.rs` includes `workspace: Option<i32>` on `KWinWindowInfo`.
- KWin parsing accepts workspace-like keys from qdbus/gdbus-style output, including scalar desktop/workspace values and list-like `desktops` output when a first numeric desktop can be parsed safely.
- Non-numeric, missing, or ambiguous workspace values stay `None`.

### X11

- `crates/sky-cua-linux/src/x11/windowing.rs` includes `workspace: Option<i32>` on `X11WindowInfo`.
- Per-window `xprop` queries include `_NET_WM_DESKTOP`.
- `_NET_WM_DESKTOP(CARDINAL) = N` is parsed as a backend-native integer.
- Sticky/all-desktops values such as `0xFFFFFFFF` stay `None`.

### Registry

- `crates/sky-cua-linux/src/windowing/registry.rs` passes `window.workspace` through from both `KWinWindowInfo` and `X11WindowInfo` into `LinuxWindowInfo`.
- `crates/sky-cua-linux/src/windowing/types.rs` passes `LinuxWindowInfo.workspace` into the public `WindowInfo` model.

## Decisions Preserved

- `workspace` is metadata only. It is not a `WindowTarget` selector.
- Values remain backend-native. There is no cross-desktop normalization.
- Missing, malformed, sticky, or ambiguous values are represented as `None`.
- Future normalized workspace UX should use a separate explicit field such as `workspace_display_index` or `workspace_label`.

```bash
cargo test -p sky-cua-linux kwin::tests
cargo test -p sky-cua-linux x11::windowing::tests
cargo test -p sky-cua-linux windowing::registry::tests
```

Broader check:

```bash
cargo test -p sky-cua-linux
```

Optional live proof:

```bash
./bin/sky-cua-client mcp
```

Then call `list_windows` in a KWin or X11 session and confirm entries include `workspace` when the window manager exposes workspace metadata.
